In a static build, server dependencies are limited to the build machine. A ReDoS in a Markdown parser might slow down a build, but visitors can’t trigger it. Request-time code runs on a live server, where anyone loading a page can reach it. Note that client dependencies ship to the browser either way, so their vulnerabilities can affect both Build-time and Request-time projects.

npm is the only package manager that audits on install at all. pnpm and Yarn audit only when you ask, with pnpm audit or yarn npm audit — and each create tool here prompts to ask which package manager is preferred.

Furthermore, many create tools swallow npm’s install output, so new projects start without ever seeing its vulnerability warnings while using npm. Shows npm audit marks the frameworks that leave npm audit results visible.

There are two ways it disappears. npm install --no-audit skips the audit entirely, which is what create-gatsby does. More often the audit still runs and the create tool captures its output: create-astro, create-preact and the TanStack CLI discard it, create-nuxt and ng new print it only when the install fails, and sv create clears the log once the install succeeds. Running npm audit manually will show the same warnings the tool hid.

  • Vulnerabilities are affected packages in the install tree, as reported by npm audit. Note that Vite’s bundled dependencies run in its dev server and at build time, not when serving production requests.
  • Advisories are distinct GitHub security advisories matched anywhere in the install tree. One advisory can flag every package that depends on the affected one, and one package can have several advisories, so this can be higher or lower than Vulnerabilities.
  • Dependencies are unique name@version pairs across the whole ecosystem, installed together in one tree. Shared dependencies count once per version. Platform-specific builds of a native package (one per OS and CPU) count once. Third-party means not published by the framework’s npm organization.
  • Snapshots are fresh installs, which pick up the newest patch releases each package allows.
  • Each ecosystem also installs its core package’s required peer dependencies, like Vite for SvelteKit or React for Next.js, and its core package’s version of Vite (or the latest Vite, if the core doesn’t use it), so older versions from stale packages don’t displace it.
